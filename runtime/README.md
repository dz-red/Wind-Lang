# Рантайм Wind: управляемая куча

В `gc.c` пока только учёт выделений. Каждый вызов `wind_gc_alloc` добавляет
запись в связный список, а `wind_gc_destroy` освобождает весь список.
Сборки недостижимых объектов пока нет, и компилятор этот модуль не использует.

Чтобы прочитать код по порядку, начни с `WindGcBlock` в `gc.c`: `data` указывает
на память для программы, `next` — на следующую запись в списке. В `wind_gc_destroy`
голова списка передвигается **до** освобождения записи: после `free` читать
из неё `next` уже нельзя.

Проверка из корня репозитория (без Boehm GC):

```sh
gcc -std=c11 -Wall -Wextra -Werror runtime/gc.c tests/gc-heap.c -o /tmp/wind-gc-heap-test
/tmp/wind-gc-heap-test
```

Следующий шаг — явные корни и ручной mark-and-sweep на тестовых объектах.
