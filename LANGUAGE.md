# Wind — справочник по языку

Каждый пример в этом файле прогнан через компилятор, вывод под примерами настоящий.

## Быстрый старт

```sh
make                    # собрать компилятор ./wind
./wind file.wnd         # собрать программу в ./app
./wind -s file.wnd      # собрать и сразу запустить
./wind --ast file.wnd   # посмотреть дерево разбора
./wind --check file.wnd # проверить исходник без запуска GCC
```

На Linux нужны `gcc` и `make`. Программы по умолчанию используют WGC;
`./wind --boehm file.wnd` собирает со старым Boehm и требует `libgc`.

### Диагностика

Режим выбирается для одного запуска. Конфигурационного файла нет.
Заголовки, пояснения и подсказки всегда на английском, независимо от локали.
Фрагменты исходника и вывод запущенной программы не переводятся.
Все три режима используют цвет в терминале. При перенаправлении `stderr`,
с `NO_COLOR=1` или `TERM=dumb` диагностика остаётся обычным текстом.

| Флаг | Вывод |
| --- | --- |
| `--diag=compact` | Одна строка `файл:строка:столбец: error[W…]: причина` на ошибку и итоговый счётчик |
| `--diag=normal` (по умолчанию) | Причина, фрагмент исходника и подчёркивание; для `return` также место объявления типа |
| `--diag=learn` | Тот же контекст, плюс объяснение и варианты исправления для ошибок с обучающей справкой |

`wind --explain W1001` объясняет ошибку команды `terminal`,
`wind --explain W1002` — синтаксические ошибки, а `wind --explain W2001` —
несовместимый тип в `return`. Для `terminal.paste` без стрелки `learn`
покажет, куда добавить `->`. Wind может вывести
несколько таких ошибок за один проход. `wind --explain W2003` объясняет,
какие значения можно подставить в `${...}`. Режимы работают и при обычной
сборке, и с `-s`: например, `./wind -s --diag=learn file.wnd`.
Если продолжить разбор после синтаксической ошибки нельзя, Wind
останавливается. Ошибки, обнаруженные только GCC, по-прежнему выводит сам GCC.

Расширение VS Code проверяет несохранённый текст через
`wind --check --stdin --diag-json путь/к/файлу.wnd`. Путь нужен для поиска
соседних модулей. В этом режиме Wind не запускает GCC и пишет по одному
объекту JSON на ошибку в stderr; позиции — с единицы, столбцы — в байтах UTF-8.

## Типы и переменные

Четыре скалярных типа: `int`, `frac`, `str`, `bool`. Тип пишется **перед именем через точку**.

```wnd
int.count = 42
frac.pi = 3,14
str.name = "Wind"
bool.ready = true
terminal.paste -> "${int.count} ${frac.pi} ${str.name} ${bool.ready}"
```

```
42 3.14 Wind 1
```

Дробное число пишется через **запятую**: `3,14`, не `3.14`. Логическое значение печатается как `1` или `0`.

Есть `var` с выводом типа и `global` для переменных верхнего уровня:

```wnd
global str.app = "wind"
var n = 10
terminal.paste -> "${str.app} ${n}"
```

```
wind 10
```

## Объявление и присваивание — не путать

При явном объявлении тип обязателен: `int.x = 5`. Если компилятор должен вывести тип сам, используй `var x = 5`.

При чтении, в том числе в аргументах функции, префикс необязателен: `x` и `int.x` означают одну переменную. Явный префикс может сделать код понятнее, если важно увидеть тип прямо на месте. Он должен совпадать с типом переменной; для преобразования используй запись вроде `int(x)`.

```wnd
int.x = 5
x = x + 3
x += 2
x -= 1
terminal.paste -> "${int.x}"
```

```
9
```

Работают `+=`, `-=`, `*=`, `/=`.

## Вывод и интерполяция

```wnd
terminal.paste -> "текст"
```

Внутри строки `${...}` подставляет значение. Внутри скобок допустимо любое выражение, включая вызов функции и индексацию.

## Условия

Один `end` закрывает ближайший открытый блок: `if`, цикл, функцию, `try` или `http.serve`. Можно уточнить имя блока (`end if`, `end while` и т. д.), но оно должно совпадать с открывающей конструкцией.

```wnd
int.age = 20
if age >= 18 && age < 65
    terminal.paste -> "взрослый"
else
    terminal.paste -> "нет"
end
```

```
взрослый
```

Операторы сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=`. Логические: `&&`, `||`.

## Циклы

**`while`** — пока условие истинно:

```wnd
int.i = 0
while i < 3
    terminal.paste -> "i=${i}"
    i = i + 1
end
```

```
i=0
i=1
i=2
```

**`repeat N`** — повторить N раз:

```wnd
repeat 3
    terminal.paste -> "тик"
end
```

```
тик
тик
тик
```

**`for V in A..B`** — по диапазону. Верхняя граница **не включается**:

```wnd
for i in 1..4
    terminal.paste -> "${i}"
end
```

```
1
2
3
```

**`loop V in COLL`** — по списку или ключам словаря (см. раздел про списки).

`break` и `continue` работают во всех циклах.

## Функции

Объявляются через `func` (синоним — `fn`), закрываются просто `end`. Возвращаемый тип обязателен.

```wnd
func square(int.x) -> int
    return x * x
end

func greet(str.who) -> str
    return "привет, " + who
end

int.n = 7
terminal.paste -> "${square(n)}"       // без префикса //
terminal.paste -> "${square(int.n)}"   // тип виден на месте вызова //
terminal.paste -> "${greet(\"мир\")}"
```

```
49
49
привет, мир
```

Рекурсия поддерживается:

```wnd
func fact(int.n) -> int
    if n < 2
        return 1
    end
    return n * fact(n - 1)
end
terminal.paste -> "5! = ${fact(5)}"
```

```
5! = 120
```

Функция без результата объявляется с `-> void`.

## Массивы

Фиксированный размер, заполняются нулями:

```wnd
int.nums[3]
nums[0] = 10
nums[1] = 20
terminal.paste -> "${int.nums[0]} ${int.nums[1]}"
```

```
10 20
```

## Списки

Динамический массив одного типа. Объявление — `<тип>.list.<имя>`.

```wnd
int.list.xs = [10, 20, 30]
xs.add(40)
terminal.paste -> "длина ${xs.len}, второй ${xs[1]}"
loop v in xs
    terminal.paste -> "  ${v}"
end
```

```
длина 4, второй 20
  10
  20
  30
  40
```

Методы: `.add(v)`, `.pop()`, `.len`, а также `len(xs)`.

> **Ставь пробел после запятой в литерале.** `[1, 2, 3]` — список из трёх чисел. `[1,2,3]` компилятор прочитает как `[1.2, 3]`, потому что запятая в Wind — десятичный разделитель.

## Словари

```wnd
dict[str,str].cfg = ["host": "localhost", "port": "8080"]
cfg["user"] = "root"
if cfg.has("host")
    terminal.paste -> "хост ${cfg[\"host\"]}"
end
terminal.paste -> "ключей ${cfg.len}"
```

```
хост localhost
ключей 3
```

Методы: `.has(k)`, `.len`. По словарю можно пройтись через `loop k in cfg` — переменная получит ключ.

## Строки

```wnd
str.a = "Wind"
str.b = str.a + " Lang"
terminal.paste -> "${str.b}, байт ${b.len}"
int.num = int("42")
terminal.paste -> "число ${int.num}, обратно ${str(int.num)}"
```

```
Wind Lang, байт 9
число 42, обратно 42
```

Склейка через `+`, сравнение через `==` и `!=`. Касты: `str()`, `int()`, `frac()`, `bool()`.

> `.len` возвращает длину **в байтах**, не в символах. Для кириллицы это вдвое больше: `"привет".len` даст 12.

## Математика

```wnd
terminal.paste -> "10 / 3 = ${10 / 3}"
terminal.paste -> "10 /% 3 = ${10 /% 3}"
frac.r = sqrt(16,0)
terminal.paste -> "корень 16 = ${frac.r}"
```

```
10 / 3 = 3
10 /% 3 = 1
корень 16 = 4
```

Остаток от деления — оператор **`/%`**, не `%`. Деление двух `int` целочисленное; чтобы получить дробь, оперируй `frac`. Функции из `math.h` доступны напрямую.

## Исключения

```wnd
try
    terminal.paste -> "пробуем"
    throw "не вышло"
catch err
    terminal.paste -> "поймали: ${str.err}"
end
terminal.paste -> "идём дальше"
```

```
пробуем
поймали: не вышло
идём дальше
```

Переменная в `catch` — строка с текстом броска. Непойманный `throw` печатает `uncaught: ...` и завершает программу с ошибкой. Вложенность до 32 уровней.

```wnd
file.write("/tmp/wind_demo.txt", "строка из Wind")
str.data = file.read("/tmp/wind_demo.txt")
terminal.paste -> "прочитали: ${str.data}"
if file.exists("/tmp/wind_demo.txt")
    terminal.paste -> "файл на месте"

```

```
прочитали: строка из Wind

```

Есть также `file.append(путь, текст)`.

## JSON

```wnd
dict[str,str].d = ["lang": "Wind", "ver": "0.1"]
terminal.paste -> "${json.encode(d)}"
var parsed = json.decode("{\"n\": 7}")
terminal.paste -> "n = ${parsed.get(\"n\").int()}"
```

```
{"ver":"0.1","lang":"Wind"}
n = 7
```

`json.encode` принимает словарь `dict[str,_]` или список. Порядок ключей на выходе не совпадает с порядком вставки — внутри хеш-таблица.

`json.decode` возвращает значение, по которому ходят методами: `.get(ключ)`, `.at(индекс)`, `.has(ключ)`, `.len`, `.type`, а достают — `.str()`, `.int()`, `.frac()`, `.bool()`.

## HTTP

Клиент:

```wnd
str.body = http.get("http://example.com")
terminal.paste -> "получено байт: ${body.len}"
```

```
получено байт: 559
```

Есть `http.post(url, тело)`.

Сервер — блок с маршрутами. Выражение справа от `->` вычисляется на каждый запрос:

```wnd
dict[str,str].info = ["lang": "Wind"]
http.serve 8080
    on "/" -> "<h1>Wind</h1>"
    on "/json" -> json.encode(info)
end
```

Сырые сокеты, HTTP/1.0, без TLS и без chunked.

## Модули Wind

`use math` загружает функции, `link` и `c.import` из соседнего `math.wnd`.
`take square from math` дополнительно проверяет, что в файле есть
`square`. Имена пока общие: `take` не скрывает остальные функции, а
совпадение имён в двух модулях вызывает ошибку. Код верхнего уровня
в импортируемом файле не выполняется.

## Внешние библиотеки

`c.import <имя>` загружает привязку к C-библиотеке. Директива пишется на
верхнем уровне. Повторный импорт той же привязки ничего не меняет.

```wnd
c.import <sqlite>

terminal.paste -> "SQLite ${sqlite.version()}"
```

Встроенная привязка `sqlite` даёт доступ к SQLite. `sqlite.version()` не
принимает аргументов и возвращает копию строки версии в памяти Wind.
Для сборки нужны заголовок `sqlite3.h` и библиотека SQLite
(`libsqlite3-dev` в Debian/Ubuntu, `sqlite-devel` в Fedora).
`--check` проверяет Wind-код без SQLite и без запуска GCC.

Директива `link` добавляет флаг `-lимя` в вызов GCC. Старый вариант
с `link "sqlite3"` и вызовом `sqlite3_libversion()` продолжает работать:

```wnd
link "sqlite3"
terminal.paste -> sqlite3_libversion()
```

### SQLite: соединения и запросы

```wnd
c.import <sqlite>

var db = sqlite.open(":memory:")
var query = sqlite.prepare(db, "SELECT ?")
sqlite.bind_text(query, 1, "Wind")
while sqlite.step(query)
    terminal.paste -> sqlite.column_text(query, 0)
end
sqlite.finalize(query)
sqlite.close(db)
```

Полный пример с записью и чтением: [`examples/sqlite-query.wnd`](examples/sqlite-query.wnd).
`open` принимает путь или `":memory:"`. `exec` выполняет SQL без чтения
результата. `prepare` готовит один SQL-оператор. Для данных подставляй `?`
и используй `bind_int` или `bind_text`: параметры нумеруются **с 1**.
SQLite копирует переданный текст, поэтому его не нужно держать в Wind.

`step` возвращает `true`, если доступна строка, и `false`, когда строк
больше нет. После конца повторный `step` не перезапускает запрос.
`reset` позволяет выполнить его снова и сохраняет значения параметров,
пока их не заменят. Столбцы нумеруются **с 0** и читаются только после
успешного `step`: `column_int` читает SQL-целое в диапазоне Wind `int`,
`column_text` копирует SQL-текст в Wind, а `is_null` проверяет `NULL`.
Строка с внутренним нулевым байтом не поддерживается.

Соединение и подготовленный запрос — разные непрозрачные типы. Сохраняй
их через `var`; числом указатель не становится. `finalize` закрывает
запрос, `close` — соединение без открытых запросов. Копия дескриптора
ссылается на тот же ресурс: закрытие делает недействительными все копии.
Ошибки SQLite и неправильное использование дескрипторов завершают
программу с сообщением. При завершении процесса SQLite-ресурсы,
оставшиеся открытыми, освобождаются отдельно от WGC.

### Внешние привязки `.windbind`

Для новой библиотеки не нужно менять или пересобирать Wind. Например,
положи рядом с входным `.wnd` файл `bindings/zlib.windbind`:

```text
header <zlib.h>
link "z"

func version() -> str = zlibVersion copy_cstr
```

```wnd
c.import <zlib>

terminal.paste -> zlib.version()
```

Один файл описывает один C-заголовок, одну библиотеку и одну или несколько
функций. Параметры пишутся как в Wind (`frac.x`), справа от `=` указывается
имя C-функции. Пример с [zlib и math](examples/ffi/main.wnd):

```sh
./wind -s examples/ffi/main.wnd
```

Порядок поиска на Linux:

1. Встроенная привязка.
2. `bindings/<имя>.windbind` в папке входного `.wnd`, даже если импорт
   записан в другом Wind-модуле и команда запущена из другой папки.
3. `$XDG_DATA_HOME/wind/bindings/<имя>.windbind`; если переменная не задана,
   `~/.local/share/wind/bindings/<имя>.windbind`.
4. `/usr/share/wind/bindings/<имя>.windbind`.

Если файл найден, но не читается или содержит ошибку, поиск не продолжается.

Параметры: `int` (C `int`), `frac` (C `double`) и `str` с обязательным
`borrow_cstr`, например `func echo(str.text borrow_cstr) -> str = echo copy_cstr`.
`borrow_cstr` передаёт `const char *` только на время вызова: C-функция
не должна изменять строку или сохранять указатель. Если данные нужны после
вызова, C-библиотека должна сделать собственную копию.

Возврат: `int`, `frac`,
`void` или `str` с обязательным `copy_cstr`. Wind проверяет число и типы
аргументов. При сборке GCC проверяет совместимость с точной сигнатурой
указателя на C-функцию, без приведений типов. `--check` читает `.windbind`,
но не запускает GCC и не проверяет наличие заголовка или библиотеки.

`copy_cstr` копирует заимствованную строку `const char *` до первого `\0`.
Wind не освобождает исходный указатель; `NULL` завершает программу с ошибкой.
Дескрипторы пока доступны только во встроенной привязке SQLite; внешние
`.windbind` не объявляют свои типы ресурсов. Структуры, буферы и callbacks
пока не поддерживаются. `.windbind` не принимает произвольный C-код,
команды или флаги GCC.

| Код | Ошибка |
| --- | --- |
| `W5001` | Привязка не найдена; `learn` показывает проверенные пути |
| `W5002` | Не удалось прочитать или разобрать `.windbind` |
| `W5003` | Не найден C-заголовок |
| `W5004` | Компоновщик не нашёл запрошенную C-библиотеку |
| `W5005` | C-объявление не соответствует сигнатуре привязки |

## Подводные камни

- Запятая — десятичный разделитель, поэтому в литералах списков нужен пробел после неё.
- Остаток от деления — `/%`.
- Повторное `int.x = ...` для существующей переменной трактуется как присваивание; с другим префиксом — ошибка компиляции.
- `.len` у строк считает байты.
- Коллекции однотипные: `[1, "hello"]` не соберётся.
- `int` 32-битный, `long` и больших чисел нет.

## Чего в языке нет

- ООП: классов, наследования, методов на пользовательских типах. Слово `class` зарезервировано в лексере, но не реализовано.
- Изолированных пространств имён модулей.
- Лямбд и функций как значений.
- Многопоточности и async — всё блокирующее.
- Сборки под Windows: только Linux.

## Как устроен компилятор

```
файл.wnd
   ↓  lexer.c        токены, переводы строк значимы
   ↓  astparse.c     рекурсивный спуск, дерево из ast.h
   ↓  astcodegen.c   генерация C + рантайм в преамбуле
output_ast.c
   ↓  gcc -O2 + рантайм WGC
./app
```

На Linux памятью программ управляет [WGC](runtime/README.md). Кодоген
отмечает живые переменные и безопасные места для сборки. GCC компилирует
сгенерированный C и исходники WGC; обычная сборка не зависит от Boehm.
Для блоков до 16 байт без внутренних ссылок WGC переиспользует слоты
на общих страницах. Правила работы языка от этого не меняются.
